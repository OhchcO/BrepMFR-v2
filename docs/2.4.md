## 2.4 机匣数据集构建

### 2.4.1 标注数据组织与质量控制

<span style="color:#C00000">【拟补表：数据文件及质量检查表，列出 STEP、标签 JSON、父图 BIN、子图 BIN、划分清单的关联键和检查项目；只填写已实际执行的检查。】</span>

数据集以完整父机匣为组织单位，将 STEP 模型与对应的逐面标签文件关联保存。数据入库前应检查模型可读性、实体范围及面数，并确认标签文件对应的是同一几何版本。经过重新导出或编辑的模型即使文件名不变，也需重新核对面索引，避免语义数组和实例数组错位。第 2.3 节完成候选匹配与人工修正后，数据集构建还需要对标签、图结构和后续训练输入进行一致性检查，不能以 JSON 文件能够导出作为样本已合格的唯一依据。

标签文件包含源模型文件名、面数、逐面语义数组和逐面实例数组。标注工具导出时检查两类数组长度与模型面数是否一致、语义代码是否在当前类别映射中，以及同一实例是否对应唯一语义类别。对于旧版标签中尚未补齐实例编号的特征面，应在实例任务的数据生成前完成复核；未匹配的面也需检查是否确为背景。当前 BIN 标签读取器主要检查整数类型、数组长度和语义与实例编号的一致性，并不再次校验语义代码是否属于图 2-1 的类别表，故入库检查仍须保留类别映射核对。

现有 JSON 导出内容未包含候选来源、模板版本或逐次修改日志。若需复核标注过程或比较人工工作量，应在数据集版本记录中另行保存源模型版本、所用模板、复核人员、误检和漏检的修正、实例拆合情况及处理时间。这些过程记录与最终标签分开管理，不能从最终 JSON 数组反推。对于试标后调整的类别定义，还应记录类别表版本及旧标签的处理方式，保证不同批次标签具有一致的语义。

### 2.4.2 标签与 BIN 数据生成

<span style="color:#C00000">【拟补图：从 STEP 与人工复核标签到父图 BIN、训练子图的转换流程，标明面索引对齐和父机匣位置继承；同时示意三维柱坐标到模型周期编码的转换。】</span>

经复核的 JSON 标签按 STEP 模型的原始面顺序记录逐面语义与实例编号。现有机匣数据转换程序读取 STEP 与对应标签，提取面、边属性及邻接关系，生成 DGL 图并保存为 BIN 文件；其中语义代码写入节点字段 `f`，实例编号写入节点字段 `i`。若无有效标签文件，转换程序将两个字段填为 $-1$，此类样本不能直接用于监督训练。转换时须保持标签数组、B-rep 面顺序与图节点顺序一致，并在加载前将 000、101 等语义代码按固定映射转换为模型的连续类别索引。具体数据集是否全部完成转换，仍应由逐件文件与运行记录确认。

对已确定轴线、原点、轴向和周向零点的机匣，径向 $r$、角度 $\theta$ 与轴向高度 $z$ 即可确定面代表点在该坐标系中的位置。当前机匣转换程序依据面 UV 网格中点的三维坐标计算这三个量，并保存归一化的 $[\bar r,\bar\theta,\bar z]$，其中 $\bar\theta=(\theta+\pi)/(2\pi)$，径向和轴向范围由转换时外部指定。第 3.2 节模型使用的 $[\bar r,\sin\theta,\cos\theta,\bar z]$ 并非增加了第四种几何位置，而是把同一个角度展开为两个连续的周期分量；由保存的 $\bar\theta$ 可恢复 $\theta=2\pi\bar\theta-\pi$，再计算正弦和余弦。

两条转换路径仍需在正式训练前统一面代表点和归一化基准：当前机匣脚本使用 UV 网格中点与外部范围，第 3 章方法使用面面积质心及完整父零件范围。此外，完整方法还需要参数曲面分支的输入。上述问题属于特征提取与模型输入的实现对齐，而非三维柱坐标不能表示机匣内位置。抽取训练子图时，应继承父机匣已经计算好的位置量，不在各子图内重新确定范围；训练前须对同一零件逐面核验两条路径的编码结果。

转换完成后，应对每件样本核对图节点数与两类标签数组长度、图边索引范围、实例编号与语义类别的一致性，以及连续特征是否存在非法数值。对于不满足条件的样本，需记录原始文件、失败原因与处理决定，并在数据集统计中说明剔除或修复情况。现有转换程序写入逐面实例编号，不能把这一字段直接表述为已生成并核验的实例关系矩阵；面间同实例关系由后续训练流程依据实例编号构建。图节点索引与原始 CAD 面身份的对应也应单独保存和检查，不能仅由两个数组长度相等推定对应正确。

### 2.4.3 数据集统计与划分

<span style="color:#C00000">【拟补表：按训练、验证、测试父机匣统计零件数、面数、实例数、实际出现的类别及子图数。拟补图：各类别的实例数或面数分布；均须由完成复核后的数据集生成。】</span>

训练、验证和测试划分以完整父机匣为单位。来自同一机匣的局部子图、不同导出版本及标注修订版应归入同一划分，以避免相同结构同时进入训练集和测试集。现有划分脚本先检查完整父图的标签，再生成父零件级划分清单；在训练父零件数允许时，优先使训练划分覆盖已出现的语义类别，若无法覆盖则报错。测试父零件保持完整图，训练和验证父零件才生成局部子图。若多个机匣属于同一设计系列，还需说明系列内结构相似性对泛化评价的影响。论文采用的最终划分应在模型比较之前冻结，并保存父零件清单及随机种子。

数据集统计应分别报告各划分的父机匣数量、B-rep 面数量、目标特征实例数量、类别覆盖和每件机匣的面数范围；训练和验证集还需报告由父机匣生成的子图数量。仅给出总体面数不足以反映少数类别是否具有可供训练或测试的样本。还应列出各类在父机匣、面及实例三个层面的频数，并记录转换失败或标签待复核的零件数量。上述数值应由完成复核和去重后的数据集计算；在统计结果形成前，不能据类别定义推断全部 30 类均已获得有效样本。

若某些二级类别在测试集中没有实例，应如实报告，并明确相应类别是否计入宏平均指标。对只出现在训练或验证集的类别，测试结果不能被解释为已经验证了这些类别的识别能力。数据集划分、类别覆盖与标签质量共同决定第 4 章真实机匣识别结果的适用范围。

### 2.4.4 标注质量与工作量评价

<span style="color:#C00000">【拟补表：在独立参考标签上比较自动预标注与人工修正后的覆盖率、误标率、实例拆合错误和用时；若另设纯人工对照，应列出相同零件上的完成质量与时间。】</span>

标注质量评价需要独立于模板选取与候选匹配的参考标签。可在未用于模板构建的机匣上，由复核人员依据统一的类别与实例定义建立参考标注，再分别评价自动预标注和人工修正后的结果。前者的目标面覆盖率以参考标签中的目标面为分母，统计被候选正确覆盖的比例；误标率则以预标注目标面为分母，统计语义或归属错误的比例。后者须核对所有目标面和背景面的最终语义，以及同类不同实例的拆分、合并情况。对于重复孔、相交特征和过渡面，还应单独统计漏标、错标及实例错误，避免总体面级准确率掩盖局部问题。

人工工作量应以实际标注过程记录为依据，包括模板准备、候选核查、误检删除、漏检补标、实例调整和总用时。若比较纯人工标注与 VF2 辅助标注，两组应使用相同的零件、类别约定、标注工具和完成标准，并分别报告模板准备、候选生成和人工复核时间。两组标签还应以同一独立参考标注检查最终质量；仅比较用时而不控制质量，不能说明流程优劣。当前标签 JSON 不保存上述过程信息，因此不能仅凭最终标签文件得出效率提升或修正量结论。
