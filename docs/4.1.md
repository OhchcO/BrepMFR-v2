# 4.1 引言

<span style="color:#C00000">【图表安排：本节引出真实机匣任务，无需单独增加图表；局部训练、整图推理和 NX 应用图分别放在对应方法小节。】</span>

第 3 章在公开合成零件数据上考察了面内几何、结构位置和实例关系对制造特征识别的作用。然而，合成零件的几何规模、特征组合和类别分布不能直接代表真实航空机匣。要判断模型能否用于机匣识别，还需在独立的真实零件上检验其语义预测、实例划分及计算开销，并使预测面与 CAD 系统中的原始面保持一致。

真实机匣可能包含大量 B-rep 面，直接以完整图训练会增加邻接关系和注意力计算的内存需求。局部连通子图可以控制训练输入规模，但模型所需的柱坐标位置应以完整父零件为参照计算，再随节点复制到子图中；验证与测试则应按完整父零件划分，避免同一零件的不同子图跨数据集出现。推理阶段需要对完整零件输出面级语义与实例关系，才能评价最终的工程识别结果。

在机匣标注样本有限的条件下，公开数据预训练可作为模型初始化方式。其效果应与相同机匣划分、训练预算和评价程序下的从零训练进行配对比较，并分别考察原始 BrepMFR 与本文方法，以区分模型结构和预训练带来的变化。相关结论只有在真实机匣数据、标签和运行记录齐备后才能给出。

预测结果还需要可靠地回写到 CAD 面对象。本文的 NX 2212 插件与独立 Python 推理程序已建立 STEP 输入、模型调用、跨内核面映射及实例展示的程序链路。程序链路的实现不等同于真实机匣识别精度或系统成功率；这两类结果应分别依据人工核验标签和 NX 现场运行记录评价。

本章先介绍局部训练与整图推理方法，再说明预训练及机匣模型适配方案，随后给出真实机匣实验的评价协议，最后讨论 UG/NX 系统实现和应用边界。
