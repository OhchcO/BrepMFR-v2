# 5.1 引言

第四章在公开 B-rep 制造特征数据上建立了面级语义识别与实例关系推理方法。真实航空机匣与公开数据中的零件在尺度、面数量、曲面组合和特征分布上可能存在差异，模型在公开测试集上的表现不能直接代替工业零件上的应用验证。机匣通常具有围绕中心轴组织的径向、周向和轴向结构，同类加工特征也可能在不同位置重复出现；这使完整零件的位置参照、局部训练样本的构造以及预测结果在 CAD 面对象上的定位成为实际应用中的关键环节。

大型机匣的完整 B-rep 图可能包含大量面和成对关系，直接以整图训练会增加存储与注意力计算负担。局部连通子图提供了控制训练规模的途径，但从完整零件截取子图后，若重新在子图内计算柱坐标归一化范围，同一面的全局位置语义就会随裁剪区域改变。为保持训练和推理的输入一致性，本章以完整父机匣为单位建立坐标规范和面索引，先在父零件上计算位置，再将对应特征继承到训练子图。数据划分也应以父机匣而非子图为单位，避免来自同一零件的局部结构同时进入训练与测试集合。

真实机匣的人工标注数量有限时，公开数据上的模型参数可作为迁移学习的起点。然而，预训练是否优于从零训练、输入表征与实例偏置是否能够迁移，都需要在相同的真实机匣划分下分别比较。本章据此安排公开数据预训练、权重迁移与局部子图微调，并以未见过的完整机匣评价面级语义和实例结果。**【待补实验数据：真实机匣的模型数量、面数与实例数、父机匣级划分、预训练及从零训练的配对结果；取得原始记录前不报告迁移收益。】**

算法输出还必须与工程软件中的面对象建立可靠对应。本文基于 Siemens NX 2212 实现独立 Python 推理程序与 NXOpen C++ 插件的集成：Python 完成 STEP 转图、模型推理和实例后处理，NX 插件负责当前部件读取、OCC/AAG 面与 NX Face Tag 的跨内核映射、结果着色和实例浏览。该系统已经形成可运行的输入到显示链路；其在具体机匣上的识别精度、映射覆盖与耗时仍须由相应的现场记录支持，不能仅由插件实现本身推断。

本章的组织如下：5.2 节讨论完整机匣建图、局部子图训练和全局位置继承；5.3 节说明公开数据预训练及真实机匣微调的比较设计；5.4 节介绍 NX 二次开发系统、跨内核面映射与结果展示，并分析适用范围和失败模式。三个部分依次回答大型机匣如何构造可训练输入、公开数据知识能否迁移，以及识别输出如何可靠落到 CAD 模型的具体面上。
