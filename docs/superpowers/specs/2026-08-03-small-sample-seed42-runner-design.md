# Seed42 Small-Sample Experiment Runner Design

## Objective

Provide one PowerShell entry point that runs the fixed four-experiment matrix
for exactly one selected MFRInstSeg sample percentage. Result directories and
prepared-dataset caches must encode the real percentage so 1%, 5%, and 10%
runs cannot overwrite or masquerade as each other.

The implementation generates scripts and tests only. It must not convert the
full dataset or start formal training during development.

## Supported Percentages and Identity

The runner accepts only these values:

| `SamplePercent` | Result label |
|---:|---|
| `0.01` | `1pct` |
| `0.05` | `5pct` |
| `0.10` | `10pct` |

Other values fail before invoking a training or test launcher. The shared
`run_mfrinstseg_experiments.ps1` launcher will derive the same label from
`SamplePercent` instead of hard-coding `1pct`.

## Entry Point

Add `tools/run_mfrinstseg_small_sample_seed42.ps1` with `Seed=42` and a
mandatory `SamplePercent` parameter. A typical invocation is:

```powershell
powershell.exe -ExecutionPolicy Bypass -File `
  "D:\Code\BrepMFR\tools\run_mfrinstseg_small_sample_seed42.ps1" `
  -SamplePercent 0.05
```

The script exposes the existing practical overrides such as raw-data path,
result root, Python executable, batch size, epoch count, worker count, and an
opt-in rebuild switch. Injectable training and test launcher paths are retained
for integration testing.

## Fixed Experiment Matrix

Each invocation runs and evaluates these four experiments in order:

1. `baseline`, default signed mapping and original UV representation.
2. `pc_aag`, default signed mapping with `param_surface`, `intrinsic`,
   `untrimmed`, and `gated` geometry configuration.
3. `affinity_only`, `positive_only` mapping and original UV representation.
4. `instance`, `positive_only` mapping and original UV representation.

This matrix keeps the two scientific comparisons controlled:

- parameter-surface representation: `pc_aag` versus `baseline`;
- dynamic instance bias: `instance` versus `affinity_only`.

The runner does not include `dynamic_no_loss`, `oracle`, cylindrical modes, or
inference-only bias-scale sweeps.

## Result and Cache Paths

Result identities use the percentage label generated by the shared launcher.
For a 5% run they are:

```text
MFRInstSeg_5pct_baseline_seed42
MFRInstSeg_5pct_pc_aag_param_surface_intrinsic_untrimmed_gated_seed42
MFRInstSeg_5pct_affinity_only_positive_seed42
MFRInstSeg_5pct_instance_positive_seed42
```

The 1% run reuses the established cache:

```text
D:\Code\Datasets\MFRInstSeg_BrepMFR_ParamSurface_v4_seed42
```

New ratios use isolated caches:

```text
D:\Code\Datasets\MFRInstSeg_BrepMFR_ParamSurface_v4_5pct_seed42
D:\Code\Datasets\MFRInstSeg_BrepMFR_ParamSurface_v4_10pct_seed42
```

All four experiments at one percentage share its single prepared cache. The
preparation contract already includes the complete geometry payload needed by
both the original UV modes and the parameter-surface mode.

## Execution and Resume Behavior

For every matrix entry, the runner:

1. derives the exact result root;
2. skips the entry when a normal `test_log.txt` already exists;
3. otherwise records pre-existing checkpoints;
4. delegates training to `run_mfrinstseg_experiments.ps1`;
5. selects only a newly created `best-*.ckpt`;
6. delegates official-test evaluation to `run_mfrinstseg_test.ps1`.

`-RebuildPreparedData` is forwarded only to the first experiment so later
entries reuse the same freshly built cache. A failed launcher stops the matrix
immediately. Resume selection binds the test log and checkpoint to the same
timestamped run directory.

## Testing

Tests use fake PowerShell launchers and temporary result directories. They must
verify:

- exact percentage labels for 1%, 5%, and 10%;
- rejection of unsupported percentages before any launcher invocation;
- the four-mode order and mapping choices;
- parameter-surface arguments only on `pc_aag`;
- shared, percentage-specific prepared cache paths;
- percentage-specific result identities;
- fresh-checkpoint selection;
- normal-test execution and complete-result skipping;
- PowerShell AST parsing for both modified scripts.

Focused and repository unit tests may run. Dataset conversion and formal
training must not run.
