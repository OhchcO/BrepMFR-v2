# NX2212 特征实例浏览器设计

## 1. 背景与目标

当前 NX2212 插件已经能够从当前打开的单实体 STEP 启动 Python 识别、读取 JSON 1.1、完成
OCC/AAG 面到 NX Face 的完整映射，并按特征实例给模型着色。识别成功后仍使用消息框和
Listing Window 展示结果，用户无法直接逐个查看识别实例。

本阶段把成功后的结果展示改为 NX 原生特征实例浏览器：

1. 识别、面映射和基础着色成功后直接打开浏览器，不再弹出成功消息框；
2. 浏览器顶部显示本次识别摘要；
3. 中间按页列出特征实例；
4. 单击实例时，只给该实例对应的 NX Face 增加临时高亮；
5. 其他实例继续保留原有识别颜色；
6. 关闭浏览器时清除临时高亮，基础着色继续保留；
7. 完整文字结果仍可在浏览器中按需查看。

系统边界不变：Python 继续只负责转换、推理和 JSON；浏览器、分页、NX Face 高亮和窗口
生命周期全部由现有 NX2212 C++ 插件负责。本功能不修改模型、JSON 1.1 或 Python CLI。

## 2. 方案选择

采用 NX 原生 Block Styler 模态窗口和 Tree 控件。

未采用的方案：

- 多标签页 Block Styler：扩展性更强，但首版信息量不需要额外层级；
- 自定义 Win32 窗口：布局自由，但窗口归属、DPI、NX 消息循环和对象生命周期更复杂；
- Listing Window 加“上一项/下一项”命令：实现简单，但不能直观浏览和直接点击实例。

模态窗口允许用户在浏览期间旋转和缩放当前模型，但阻止执行其他建模命令。这样可以保证
浏览会话中的 Work Part、Body 和 NX Face Tag 不会在窗口存活期间失效。

## 3. 固定范围

### 3.1 首版支持

- NX2212、VS2019/v142/x64；
- 仅在 JSON 1.1 面映射完整且基础着色成功后打开浏览器；
- 所有识别实例保持各自的基础颜色；
- 实例单选，当前实例增加 NX 临时高亮；
- 50 个实例一页，超过 50 个时显示上一页、下一页和页码；
- 实例少于或等于 50 个时隐藏分页控件；
- 顶部摘要、实例列表、当前实例详情和完整文字结果入口；
- 关闭窗口时可靠清除浏览器产生的临时高亮；
- 浏览器关闭后不撤销基础颜色、不保存 Part。

### 3.2 首版不支持

- 模型无完整面映射时打开只读浏览器；
- 多选、多个实例同时临时高亮；
- 隐藏其他实例、透明化 stock、隔离显示或自动调整视图；
- 浏览器打开期间切换 Work Part 或继续建模；
- 搜索、过滤、按列排序和按特征类型分组；
- 修改颜色、恢复识别前颜色或持久化浏览器选择；
- Python 常驻服务、JSON 新版本或模型接口修改。

## 4. 用户流程

1. 用户打开未经修改的单实体 STEP，点击 BrepMFR 插件；
2. 现有进度窗口继续展示 Python 识别过程；
3. 插件完成 JSON 校验、全局面映射和原子基础着色；
4. 插件构造不可变的浏览会话数据并直接打开模态实例浏览器；
5. 浏览器初始不增加临时高亮，模型只显示各实例基础颜色；
6. 用户单击一行：先清除上一个实例的临时高亮，再高亮当前实例的全部 NX Face，并更新
   底部详情；
7. 用户翻页：清除当前临时高亮、切换当前页，详情恢复为“请选择实例”；
8. 用户点击“查看完整结果”：在已有 NX Listing Window 中输出本次完整文字结果；
9. 用户点击“关闭”或窗口右上角关闭：清除临时高亮并结束浏览会话，基础颜色保留。

浏览器发生局部 UI 或高亮错误时，显示明确错误并安全关闭浏览器；已经成功完成的识别和基础
着色不回滚。推理、映射或基础着色失败时沿用现有错误/结果展示路径，不创建浏览器。

## 5. 窗口布局

窗口标题为 `BrepMFR 特征实例浏览器`，使用一个随 DLL 分发的 `.dlx` 文件。

### 5.1 顶部摘要

摘要为只读多行区域，至少显示：

- 面数量；
- 特征实例数量；
- BIN 缓存命中状态；
- Python pipeline 用时；
- Python 进程总用时；
- 已映射面数量，例如 `41/41`；
- 已着色实例数量；
- 面映射用时。

摘要使用结构化字段渲染，不从已有中文 `summary_utf8` 中反向解析。STEP 路径、结果 JSON
路径和最大映射误差保留在完整文字结果中，避免顶部区域过长。

### 5.2 实例列表

Tree 控件按 `instance_id` 升序显示当前页，固定列为：

| 列 | 内容 |
| --- | --- |
| 实例 | `instance_id` |
| 特征类型 | `feature_name` |
| 面数 | 实例包含的面数量 |
| 置信度 | 四位小数 |

Tree 只允许单选，节点不允许编辑、拖放或删除。节点与实例的关系通过会话内稳定索引维护，
禁止从显示文本中解析 `instance_id`。

### 5.3 分页与详情

页大小固定为 50。分页规则为：

- `page_count = max(1, ceil(instance_count / 50))`；
- 实例数量不超过 50 时隐藏“上一页”“下一页”和页码；
- 第一页禁用“上一页”，最后一页禁用“下一页”；
- 页码显示 `第 X / Y 页`；
- 翻页后不自动选择第一行，避免无意改变模型高亮。

底部详情显示当前实例的特征名、置信度、OCC/AAG 面编号和 NX Face Tag。没有选中项时显示
“请选择一个特征实例”。按钮包括“查看完整结果”和“关闭”，不提供 Apply/OK 语义。

## 6. 数据模型与代码边界

新增与 NX API 无关的浏览器数据模型：

```cpp
struct InstanceBrowserRow
{
    int instance_id;
    std::string feature_name_utf8;
    double confidence;
    std::vector<int> occ_face_indices;
    std::vector<FaceKey> nx_face_tags;
    int color_index;
};

struct InstanceBrowserSummary
{
    int face_count;
    std::size_t instance_count;
    bool cache_hit;
    double pipeline_seconds;
    std::chrono::milliseconds process_elapsed;
    std::size_t mapped_faces;
    std::size_t colored_instances;
    std::chrono::milliseconds mapping_elapsed;
};

struct InstanceBrowserModel
{
    InstanceBrowserSummary summary;
    std::vector<InstanceBrowserRow> rows;
    DisplayText complete_text;
};
```

实际命名可在实施时调整，但职责保持如下：

- `instance_browser_model`：合并 `SuccessResult`、`MappingDisplay` 和 `DisplayText`，验证每个
  识别实例恰好有一条颜色记录并按 ID 排序；
- `instance_browser_state`：纯 C++ 分页、选中项和按钮状态，不 include NXOpen；
- `nx_instance_browser`：加载 `.dlx`、创建 Block Styler Tree、绑定回调、调用 NX 高亮接口；
- `PluginHost`：成功路径从 `ShowSuccess` 演进为 `ShowInstanceBrowser`；错误展示保持不变；
- `plugin_runtime`：映射和着色成功后构造浏览器模型，模态展示并等待其关闭。

`ColorPlan.instances` 已包含 `instance_id -> nx_face_tags`，`SuccessResult.instances` 已包含特征名、
置信度和 OCC 面编号，因此不增加 JSON 字段，也不重新运行面映射。

## 7. 高亮生命周期

临时高亮只使用 NX `DisplayableObject::Highlight()` / `Unhighlight()`，不使用
`DisplayModification`，也不改变 Face 颜色属性。

选择切换必须遵循：

1. 对上一实例记录的全部 Face 调用 `Unhighlight()`；
2. 通过本次会话快照验证 Work Part/Body 身份和面数量仍一致；
3. 将新实例的 Face Tag 解析为当前 Part 中的 Face；
4. 只有全部 Face 都有效时才逐个 `Highlight()`；
5. 任一步失败时撤销本次已经增加的高亮，清空选择并报告错误。

对同一行重复选择保持幂等。分页、关闭、异常退出和浏览器析构都调用同一个
`ClearTemporaryHighlight()`；该函数应允许重复调用且不抛出异常。浏览器不撤销或覆盖实例
基础颜色。

由于窗口为模态，首版不允许用户执行建模命令；快照复核仍保留为防御性检查。插件卸载策略
必须保证 Block Styler 窗口和回调结束前 DLL 不被卸载。

## 8. 完整文字结果

现有 `FormatSuccessDisplay` 继续生成完整文本，避免改变既有结果格式和测试基线。正常成功流程
不自动打开 Listing Window，也不弹成功消息框；用户点击“查看完整结果”时才清空或分隔并
写入本次 `listing_lines_utf8`。

为了避免同一按钮重复写入大量内容，会话记录本次完整结果是否已经输出：首次点击写入并
打开 Listing Window，后续点击只把已打开窗口带到前台或再次显示，不重复追加文本。

## 9. 错误行为

- JSON 1.0、映射不可用或映射失败：保留现有“识别成功，但面映射失败”结果展示，不打开
  实例浏览器；
- 基础着色失败：不打开浏览器，沿用现有诊断；
- `.dlx` 缺失或无法加载：识别和着色结果仍有效，显示包含 `.dlx` 路径的错误；
- 浏览器模型中缺少实例、重复实例或存在无效 NX Tag：拒绝打开浏览器并报告一致性错误；
- 单次高亮失败：清除临时高亮、保留基础颜色，错误信息包含实例 ID；
- Listing Window 输出失败：浏览器继续可用，只报告文字展示失败；
- 关闭清理失败：尽最大努力清理所有已记录 Face，不传播析构异常。

## 10. 构建与部署

新增 `.dlx` 文件作为源码资产纳入仓库，构建后复制到 DLL 所在目录。运行时通过
`ModuleDirectory()` 构造绝对路径，不依赖 NX 当前工作目录，也不要求用户配置额外路径。

项目继续使用 VS2019/v142/x64 和 NX2212 SDK。纯状态与模型构造代码加入
`BrepMFRNx2212RuntimeTests`；包含 Block Styler/NXOpen 的适配层只加入插件 DLL 项目。

## 11. 测试与验收

### 11.1 原生 C++ 自动化

- 浏览器模型正确合并识别实例和颜色记录；
- 实例乱序时稳定按 `instance_id` 排序；
- 缺少、重复或多余颜色记录时失败封闭；
- 0、1、50、51、100、101 个实例的页数、页边界和按钮状态正确；
- 翻页清除选中项，上一页/下一页不会越界；
- 选择同一实例幂等，切换实例先清除旧高亮；
- 关闭和异常路径始终请求清理临时高亮；
- 成功路径调用浏览器一次，不再调用旧成功弹窗；
- 映射/着色失败路径不打开浏览器；
- 现有结果格式、进程、映射和着色测试继续通过。

### 11.2 仓库验证

- 完整 `pytest` 回归通过；
- `BrepMFRNx2212RuntimeTests` Release/x64/v142 通过；
- `BrepMFRNx2212.dll` Release/x64/v142 构建成功；
- 输出目录包含 DLL、配置示例要求的运行配置和实例浏览器 `.dlx`；
- DLL 导出和卸载策略保持有效。

### 11.3 NX2212 现场验收

使用已验证的 41 面、9 实例黄金 STEP：

1. 点击插件后完成 41/41 面映射和 9 个实例基础着色；
2. 成功消息框和 Listing Window 不再自动弹出，实例浏览器直接打开；
3. 顶部摘要的面数、实例数、缓存状态和三项计时与现有结果一致；
4. 9 个实例全部在第一页，分页控件隐藏；
5. 逐行单击时只有当前实例增加临时高亮，其他实例原颜色不变；
6. 切换实例后旧实例高亮消失，新实例高亮正确；
7. “查看完整结果”显示既有完整文字结果且重复点击不重复追加；
8. 关闭浏览器后临时高亮全部消失，9 个实例基础颜色保留；
9. 使用构造的 51 个实例浏览模型验证两页切换、边界按钮和翻页清理；
10. 缺失 `.dlx` 时出现可诊断错误，不影响已完成的基础着色。

## 12. 后续扩展

搜索、按特征类型过滤、按列排序、双击定位、视图自动缩放、隔离显示、恢复原色以及模型无
完整映射时的只读浏览器均留作后续功能。首版优先保证：结果直接可见、实例选择可靠、NX
Face 高亮不污染基础颜色、窗口关闭后没有残留临时状态。
